# 0.5.0 plan: shared contract for the parallel work

The work is split into three parallel tracks. Each track stays inside its own file scope and follows the contracts below, so the coordinator can merge `feat/systems` first and `feat/content` second.

Not in scope: a short-run / flight-length mode (the user asked for this to wait).

## Track A: systems (branch `feat/systems`, worktree `~/Projects/azs-systems`)
1. **Chests.** Elites and the boss drop a `chest` item. Picking it up pauses the game and shows a chest screen: open it and get 1 upgrade (elite) or 3 (boss), shown one after another. An upgrade is an evolution when one is eligible, otherwise a random level-up of an owned skill or passive, otherwise gold.
2. **Weapon evolutions.** The data is `C.EVOLUTIONS = { { weapon = "crusader", passive = "might", into = "crusader_evo" }, ... }`. A recipe is eligible when the weapon is at `C.MAX_WEAPON_LEVEL` and the passive is owned at any level. Only chests evolve. The evolved weapon:
   - replaces the base weapon in the same slot;
   - is defined in `C.WEAPONS` with `evolved = true`, the same `type` mechanics, stronger `base` and `levels = {}`;
   - is never offered on level-up.

   Write recipes and evolved weapons for paladin, rogue and druid: one per skill, 15 in total.
3. **Gold and the shop.** Kills drop gold sometimes (`coin` item; the elite drops a pile and the boss a lot). `S.gold` counts it, and at run end it is banked into `db.gold`. A Shop button on the class screen opens a shop panel with permanent upgrades bought with gold, each with ranks and rising cost:
   - Might, Armor, Max HP, Recovery, Swiftness, Greed (pickup range), Growth (XP);
   - Reroll: N rerolls per run on the level-up screen, R key;
   - Skip: N skips, S key.

   Sim takes them through `Sim.New(opts.meta)`, where meta is a table of ranks. Keep Sim pure, with no db access.
4. **Curses (difficulty).** Selectable on the class screen, stacking and persisted in `db.curses`:
   - Horde: +50% spawn rate;
   - Brutal: +60% enemy hp;
   - Haste: +25% enemy speed;
   - Frail: -30% max HP.

   Each active curse adds +25% XP and +50% gold. Show the multiplier.
5. **Results screen.** It replaces the plain game-over panel. It shows time, level, kills, gold earned and damage per skill as bars with DPS.
   - Damage attribution: `damage()` adds `amt` to `S.dmgBy[S.curSrc or "other"]`.
   - The weapon dispatcher sets `S.curSrc = w.id` before calling `W[type]`.
   - Every entity a weapon spawns that hits later (projectile, zone, falling star, dot, minion) stores `.src = weapon id`, and the code sets `S.curSrc = obj.src` before applying its damage.
   - Poison and dot ticks also need `.src`.
6. **Achievements and unlocks.** Store them in `db.ach`. Show a toast with a WoW achievement-style frame, and add a list panel on the class screen. Examples:
   - survive 5 / 10 minutes;
   - win with each class;
   - kill the boss;
   - 1000 kills in one run;
   - evolve a weapon;
   - win with 2+ curses.

   Unlocks:
   - "survive 10 min as Rogue": +1 Reroll;
   - "evolve any weapon": a 6th weapon slot;
   - "win with every base class": a cosmetic title on the class screen.

   Keep achievements data-driven in Content (`C.ACHIEVEMENTS`), with checks that are pure functions of the run summary.
7. **Sound.** Use WoW built-in `SOUNDKIT` ids via `PlaySound`, with no new files, through a small `ns.Sfx(name)` with throttling (no more than N per 0.1 s per name). Sounds: level-up, chest open, evolution, pickup coin (throttled), player hit, boss spawn, death, victory, achievement. Add a `/azs sound` toggle. Sim raises events through the existing hooks; Main/UI play the sounds.
8. **Guild leaderboard.** In `Social.lua`:
   - `C_ChatInfo.RegisterAddonMessagePrefix("AzSurv")`;
   - on run end, if in a guild, `C_ChatInfo.SendAddonMessage("AzSurv", "R1:<class>:<seconds>:<kills>:<level>:<won>", "GUILD")`;
   - received bests are stored in `db.guild[name] = {class, t, kills, ...}` (best per player per class);
   - a "Guild" tab on the class screen lists the top entries;
   - a `/azs board` slash command prints them.

   Throttle the message to one send per run end. Ignore malformed messages.
9. **Save format.** Bump `Sim.SAVE_VERSION` to 2 and add gold, `dmgBy`, meta and curses. Keep `tests/test_save.lua` passing, extended for the new fields.

## Track B: content (branch `feat/content`, worktree `~/Projects/azs-content`)
1. **Three new classes, five skills each.** Each class also gets its own evolutions, written as data in the same `C.EVOLUTIONS` format with `evolved = true` weapons (15 more). Append the classes to `C.CLASS_ORDER`.
   - **Mage** `hero_mage`, `ClassIcon_Mage`, fragile, regen 0:
     - `frostbolt`: proj, slows, art `frostbolt`; the start skill;
     - `fireball`: proj that explodes in an area, art `fireball`;
     - `arcane`: Arcane Missiles, several homing projectiles, art `arcane`;
     - `blizzard`: a zone that damages and slows, placed on enemy clusters, art `blizzard`;
     - `frostnova`: nova that roots.
   - **Warlock** `hero_warlock`, `ClassIcon_Warlock`:
     - `shadowbolt`: proj, art `shadowbolt`; the start skill;
     - `corruption`: a dot that spreads on death;
     - `rainfire`: Rain of Fire, falling fire zones, art `felfire`;
     - `drainlife`: a beam on the nearest enemy that heals the player; draw it with Render's line fx;
     - `imp`: a pet that follows and shoots firebolts, art `imp`, projectile `felfire`.
   - **Hunter** `hero_hunter`, `ClassIcon_Hunter`:
     - `autoshot`: piercing arrows, art `arrow`; the start skill;
     - `multishot`: a fan of arrows;
     - `trap`: Explosive Trap, a mine that detonates in an area, art `trap`;
     - `volley`: rains arrows in an area;
     - `wolf`: a pet that chases and bites, art `wolf`.

   Pets are a new weapon type: a minion with its own position and AI. Leave existing weapon types untouched; only add new types to `W`.
2. **New enemy behaviours.** Add these through an `ai` field on `C.ENEMIES` entries, dispatched in Sim's enemy update. A missing `ai` keeps today's chase behaviour.
   - `caster`: skeleton mage, art `caster`, `ai = "ranged"`. It keeps about 220 px away and fires slow `enemybolt` projectiles; the player dodges them. Enemy projectiles are a new pool.
   - `charger`: worgen, art `charger`, `ai = "charge"`. It telegraphs, then dashes in a straight line.
   - `ooze`: art `ooze`, `ai = "split"`. On death it splits into 2 `oozelet` (same art, small).

   Add them to the waves from about 2:30 onwards.
3. **Map events and pickups.**
   - Ring of skeletons: a ring that closes in at about 3:30 and 6:30.
   - Gold goblin: art `goblin`. It flees, despawns after 15 s and drops a lot of coins (the `coin` item from track A; if it isn't there, just define item kind `coin` with value and let the merge unify).
   - Braziers: art `brazier`. They spawn around the player, take damage from weapons and drop a random pickup:
     - `magnet`: collects all gems on screen;
     - `chicken`: heals 30%;
     - `bomb`: damages everything on screen.

     Pickup art: `magnet`, `chicken`, `bomb`.
4. **Zone themes.** Main reads `C_Map.GetBestMapForUnit("player")` and passes `opts.zone` into Sim.New. `C.ZONES` maps zone name or map ID to `{ ground = "ground_tirisfal", tint = {...}, mix = {...optional wave overrides} }`.
   - Ground art keys: `ground_tirisfal`, `ground_barrens`, `ground_elwynn`, `ground_snow`.
   - An unknown zone falls back to today's `ground` and waves.
   - Main also needs a sensible mapping from zone to theme. Use the continent/parent map via `C_Map.GetMapInfo(...).parentMapID` and keyword matching on the map name, so most zones get some theme.
5. **Save.** New entity state (pets, enemy projectiles, braziers, zone) must survive `Sim.Serialize`/`Deserialize`, or be safely dropped on load if transient. Extend `tests/test_save.lua` to cover the new classes.

## Shared rules
- Every art key must render with a fallback (WoW icon or circle) when the .tga is missing.
- Lua 5.1, pure Sim with no WoW API. Tests: `lua5.1 tests/run_addon.lua 30`, `NOART=1`, `luajit`, `tests/test_save.lua` and `tests/run_sim.lua` (bots should still win sometimes).
- Commit on your branch with `-c user.name="$(git -C ~/Projects/polesim-gear config user.name)" -c user.email="$(git -C ~/Projects/polesim-gear config user.email)"`. Do NOT push and do NOT install.
- New WoW API calls: check names and argument order against wow-ui-source / warcraft.wiki.gg, and list every new API used in the final report.
